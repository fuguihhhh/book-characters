# 文学人物动态匹配网站（演示版）

这是一个纯前端、可直接运行的“互动文学人物匹配”程序。

## 核心不是固定打分表

程序实现了：

1. **人物概率池**
   - 所有人物开始时都有先验概率。
   - 每次回答后，用“该人物在这个具体情境下做出该选择的可能性”更新后验概率。
   - 不会因为一次回答就把人物永久淘汰。

2. **题目置信度**
   - 每道题有 confidence。
   - 对某角色缺乏直接文学证据时，结果向均匀分布回缩，降低这题对最终判断的影响。

3. **动态选题**
   - 每一步都重新计算哪几道题最能区分当前候选角色。
   - 使用“预期后验熵”计算近似信息增益。

4. **温度随机**
   - 不永远选择数学上最优的那一道。
   - 系统把前几道高质量候选题转成概率分布再抽取。
   - 前期温度高，路线变化大；后期温度低，逐渐收敛。

5. **反转机制**
   - 当某个人物明显领先时，提高“能挑战当前领先人物”的题目的权重。
   - 防止形成“前面猜了谁，后面一直验证谁”的确认偏差。

6. **题型新鲜度**
   - 最近连续出现同一主题，会主动降权。
   - 防止连续出现多个战争/爱情/道德题，保持互动小说感。

7. **可见变化**
   - 每次回答后显示“故事正在靠近哪些人物、远离哪些人物”。
   - 但说明后续仍可反转。

8. **结果不是只有一个人物**
   - 输出 Top 5。
   - 另外计算“同行者 / 吸引对象 / 对手”，且不简单等同于“与你最像”。

## 运行

直接双击 `index.html` 即可。
也可以用 VS Code Live Server、GitHub Pages 或任何静态服务器部署。

## 当前数据规模

演示版：
- 24 个经典人物
- 20 道沉浸式情境题
- 每次通常 11–14 题

程序结构可扩展到 640+ 人物。真正扩展时，最主要的工作不是改算法，而是继续补充：
- CHARACTERS
- QUESTIONS
- 各题中角色的选择概率 `p`
- 题目置信度 `confidence`

## 扩展到 640 人物时的建议

不要手工要求“640 人 × 200 题”全部填写。
更适合的方法是：

- 每个角色只对自己有充分依据的情境题填写概率；
- 缺失值默认 `[0.25,0.25,0.25,0.25]`；
- 再给每个“角色-题目”单独增加 confidence；
- 后续可用脚本或后台编辑器批量维护。

正式版建议将 `q.confidence` 升级为：
`q.confidenceByCharacter[characterId]`
这样同一道题对不同人物可有不同证据强度。
